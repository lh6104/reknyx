INNOVATION HACKATHON

AI Agent for Automated Penetration Testing
Final Participant Problem Statement | AI-Powered Unified VAPT Agent



1. Background
Penetration testing involves several stages, including reconnaissance, attack-surface
discovery, scanning, enumeration, vulnerability analysis, validation, and reporting.

These stages typically require multiple tools and substantial manual correlation.
Cybersecurity analysts may spend more time combining and interpreting outputs from
different tools than actually analyzing security risks.

This challenge aims to address this problem by developing a context-aware, adaptive, and
evidence-driven AI agent that reduces the manual workload involved in penetration testing.



2. Problem Statement
Design and build a conversational AI agent that guides an authorized security assessment
from initial reconnaissance through the generation of a client-ready VAPT report.

Similar to an AI research assistant that selects appropriate information sources, interprets
their results, and synthesizes meaningful answers, the proposed agent must be capable of:

    Selecting appropriate cybersecurity tools based on the assessment requirements.
    Interpreting scan results and identifying potential vulnerabilities.
    Deciding what needs to be investigated next.
    Correlating evidence obtained from multiple security tools.
    Prioritizing identified risks.
    Explaining its decisions and the reasoning behind its actions.

The agent must demonstrate actual security reasoning rather than blindly executing a
predefined sequence of scanners.

Important Security Boundary:

All live testing must remain strictly within organizer-provided and explicitly authorized
sandbox/lab targets.

Active exploitation or offensive proof-of-concept validation requires explicit human approval
before execution.



3. Expected User Experience and End-to-End Workflow
The AI agent should support the following end-to-end assessment workflow:

Analyst Request → Agent Planning → Approved Scan Orchestration → Result Ingestion → AI
Analysis → Risk Prioritization → Human Review → Unified VAPT Report

The workflow should include:

 1. Analyst Request: Accept a natural-language assessment request along with the
    authorized target and scope.
 2. Agent Planning: Generate an assessment plan by selecting appropriate tools based on
    the target and explaining the rationale behind each selection.
 3. Approved Scan Orchestration: Execute the approved security scans using the selected
    tools.
 4. Result Ingestion: Collect and process the outputs generated by the integrated security
    tools.
 5. AI Correlation and Analysis: Correlate findings from multiple tools and perform
    evidence-based analysis.
 6. Risk Prioritization: Evaluate identified vulnerabilities and prioritize them based on their
    associated risks.
 7. Human Review and Approved Validation: Allow an analyst to review findings and
    explicitly approve any active validation.
 8. Professional Reporting: Generate a unified, professional VAPT report suitable for client
    delivery.

The agent should also:

    Display assessment progress, tool execution status, key decisions, and failures.
    Explain why a particular subsequent scan or investigation is necessary.
    Avoid unnecessary or repeated actions.
    Clearly distinguish between observed evidence and AI-generated inferences.

5. Functional Requirements
The proposed AI agent must demonstrate the following functional capabilities:

5.1 Scope Enforcement
Register approved lab targets, exclusions, permissions, and scan boundaries. The agent must
reject any actions that fall outside the authorized scope.

5.2 Adaptive Planning

=== PDF PAGE 4 ===
Select relevant tools based on discovered hosts, services, technologies, and previously
obtained results. The agent must explain the rationale behind its next steps.


5.3 Scan Orchestration
Execute permitted scans, monitor running jobs, handle timeouts and errors, and maintain
records of tool execution status.

5.4 Normalization and Correlation
Map findings obtained from different tools into a common data model. Merge genuine
duplicate findings without hiding distinct affected assets or supporting evidence.

5.5 Evidence and Validation
Preserve the following information for identified findings:

    Source tool.
    Affected asset.
    Timestamps.
    Raw references.
    Supporting evidence.
    Confidence level.
    Confirmed or suspected status.

5.6 Risk Prioritization
Evaluate vulnerabilities by considering:

    Severity and CVSS.
    Exposure.
    Exploitability.
    Asset impact.
    Confidence level.

The agent must not generate fabricated CVEs, proof, or risk scores.

5.7 Human-in-the-Loop
Require explicit human approval before performing any active exploitation or offensive
validation. The approval and its outcome must be recorded.

5.8 Reporting
Generate a readable, client-ready VAPT report containing executive and technical views,
remediation recommendations, and assessment limitations.

10. Judges' Live Demonstration Checklist
During the final demonstration, judges will evaluate the following capabilities:

 1. Enter an authorized target and conversational assessment request, and demonstrate
    scope validation.
 2. Show the AI agent generating an assessment plan with clear tool selections and
    reasoning.
 3. Execute or import multi-tool assessments, displaying genuine tool execution status and
    traceable outputs.
 4. Demonstrate normalization, cross-tool correlation, duplicate/false-positive handling, and
    uncertainty.
 5. Demonstrate severity/risk prioritization and an explicit human-approval checkpoint
    before any active validation.
 6. Download and inspect the final unified VAPT report, tracing a reported finding back to its
    original source evidence.
 7. Demonstrate safe failure handling and honestly identify unsupported integrations.

13. Safety, Ethics and Assessment Integrity
Participants must adhere to the following security and ethical requirements throughout the
assessment:

    Do not test third-party or public systems.
    Do not evade authorization.
    Do not perform uncontrolled exploitation.
    Do not fabricate scanner output.
    Respect organizer-provided lab boundaries, rate limits, and credentials.
    Store sensitive scan data securely.
    Ensure that LLM-generated conclusions are grounded in actual tool evidence.
    Ensure every action is attributable through an audit trail.



Success Criterion
Judges should see a working AI security assistant that reduces manual coordination and
reporting effort while keeping the human analyst in control of consequential actions.
