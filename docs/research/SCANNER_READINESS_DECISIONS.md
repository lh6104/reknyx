This document adds decisions to the existing [scanner research](SCANNER_RESEARCH.md), [contracts](../superpowers/specs/2026-11-02-corevapt-contracts.md), [worker plan](../superpowers/plans/2026-11-02-03-worker-scanners.md), and [architecture review](ARCHITECTURE_FIT_REVIEW.md); it does not change those files or freeze executable contracts.

## 1. Decisions to carry into the contract gate

Keep **Nmap live discovery + ZAP packaged baseline live + Greenbone native XML import** as the intended three-tool set. Preserve Greenbone's infrastructure vulnerability coverage if a lawful native export is obtainable. Do not deploy a Greenbone stack merely to claim adapter breadth. Current availability stays `planned`, evidence level `none`, until the implementation and acceptance gates below pass.

| Adapter / consumer schema | Fixed acceptance selector for v1 | Explicit exclusion / remaining gate |
| --- | --- | --- |
| `nmap_xml_v1` / `nmap_discovery_v1` | XML root `/nmaprun`, `scanner="nmap"`, **`xmloutputversion="1.05"`**; immediate `host` children and their immediate `ports/port` children | Other XML versions require a separately reviewed compatibility extension. Old upstream 1.03 samples are references, not positive v1 fixtures. Pin an actual binary/package or image digest and capture 1.05 lab output before availability |
| `zap_traditional_json_v1` / `zap_baseline_v1` | Packaged baseline **Automation Framework (AF) path**, `-J baseline.json`, report template **`traditional-json`**; top-level object with `site[]`, then `alerts[]`, then `instances[]` | Reject alert-API arrays/objects, SARIF, `traditional-json-plus`, and the legacy core-report route. Pin script, ZAP core, reports/automation/passive-rule add-ons, template hash, image digest, and a matching captured report |
| `greenbone_native_xml_v1` / import-only | Native **scan** report with embedded **GMP 22.6 or 22.7** and the single data-report selectors below; native XML format identifier `a994b278-1f62-11e1-96ac-406186ea4fc5` when an export envelope supplies it | Reject GMP 9.0, unversioned/other versions, audit/compliance, delta/compare, assets, anonymous-export format, non-native formats and Base64 bodies. A genuine 22.6/22.7 export and source/export manifest remain required |

These are **selected design limits**, not claims that those parsers exist or all releases are compatible. A missing discriminator produces `unsupported_format`; a mismatching runtime preflight keeps the capability unavailable. G0 must add bounded source-specific schemas and typed coverage/diagnostic fields to `ParsedBatch`; a generic `fields: dict` is insufficient. Numeric strings are validated before conversion and their originals are retained.

Apply the proposed G0 input limits consistently: 20 MiB raw upload, depth64, 10,000 records and a 10-second isolated parse budget. These are selected limits awaiting tests. Disable XML external entities, network/file resolution, DTD loading and XInclude. A legitimate Nmap DOCTYPE may be accepted without resolving it; internal entity declarations/expansion remain rejected. Ignore stylesheet processing instructions rather than following their file/network URLs. Preserve raw bytes before parsing and return the agreed `malformed|unsupported_format|unsafe_xml|resource_limit` rejection with a detailed reason.

Nmap's inspected current source defines XML **1.05**; the official book example and the Ndiff samples inspected here use 1.03. Pinning only “Nmap XML” would hide that difference. The public download page listed release 7.993 when accessed, but no installed binary or release-package contents were checked. The chosen XML format does not assert that a local package matches it. [Pinned Nmap header](https://github.com/nmap/nmap/blob/c75732fb03755051a8e131df09462230811056f7/nmap.h#L122), [download page](https://nmap.org/download.html), [XML documentation](https://nmap.org/book/output-formats-xml-output.html).

ZAP does not provide a schema-version field for this report. `@version` identifies the producer, not a JSON schema. Therefore the consumer version above means a documented shape plus the pinned template/source fingerprints in the [inspection manifest](sources/scanner-readiness.json). Unknown optional root sections may be retained as bounded opaque metadata; unexpected required field types fail validation. A later template/image change requires reinspection and native fixture acceptance rather than silently broadening support. [Pinned template](https://github.com/zaproxy/zap-extensions/blob/0190c80bd420c3bb900db944c7415901d1e677e2/addOns/reports/src/main/zapHomeFiles/reports/traditional-json/report.json).

## 2. Native selectors and field maps

### Nmap

Use `/nmaprun/host` for host observations and `/nmaprun/host/ports/port` for explicit service/port observations. An aggregated `extraports` entry remains coverage metadata; do not invent one observation for every inferred port. Unknown NSE/OS/trace content stays in the raw artifact and is outside this discovery parser's finding coverage.

| Native path, relative to the selected root/record | Normalized destination / rule |
| --- | --- |
| `/nmaprun/@version`, `@xmloutputversion`, `@start`, `/runstats/finished/@time` | Producer/schema identity and source start/end timestamps; keep the receipt timestamps separately |
| `host/status/@state,@reason`; `host/address/@addr,@addrtype`; `host/hostnames/hostname` | Host state and typed addresses; choose an IPv4/IPv6 asset address explicitly, never a MAC address; preserve aliases without independently resolving them |
| `port/@protocol,@portid`; `port/state/@state,@reason` | `protocol`, validated integer `port`, source state/reason; filtered/closed states are retained as observations, not open-service claims |
| `port/service/@name,@product,@version,@extrainfo,@tunnel,@method,@conf`; `service/cpe[]` | Source service fields and CPEs; absent version stays null; `method=table` is a port-table attribution, not a detected software version |
| Host ordinal and port ordinal / native tuple | Artifact-scoped `native_record_key`; record an exact XPath locator including ordinals, plus native address/protocol/port. Nmap supplies no universal result UUID |
| `/runstats/finished/@exit,@errormsg`; `/runstats/hosts`; `/scaninfo`; `host/@timedout` when present | Completion and coverage diagnostics, not vulnerability counts |

Every mapped record is `kind=host|service`; this profile emits **zero automatic vulnerability findings**. Preserve `service_conf` as a source scale, including 0 when present; do not turn it into a calibrated probability. The inspected DTD permits 0–10. Preserve unknown new enum values as raw diagnostics rather than coercing them to a known state. [Pinned DTD](https://github.com/nmap/nmap/blob/c75732fb03755051a8e131df09462230811056f7/docs/nmap.dtd), [service detection](https://nmap.org/book/man-version-detection.html).

### ZAP packaged baseline

Use JSON Pointers `/site/{s}/alerts/{a}/instances/{i}`. Each instance becomes one source observation before correlation; one alert group with two instances must not collapse to one location. The artifact ID plus pointer forms the ingestion key. Preserve the instance `id` as a source value, but do not rely on it being globally unique or positive: the inspected upstream test uses `-1`.

| Native field | Normalized destination / rule |
| --- | --- |
| `@programName`, `@version`, `created`, `@generated` | Producer and report-generation metadata; use an unambiguous `created` instant when supplied. Localized `@generated` alone is insufficient to invent a UTC scan time |
| `site[].@name,@host,@port,@ssl` | Source site/origin and bounded asset identity; independently validate each instance URI against the expected origin. Do not merge historical sample addresses into live assessment assets |
| `alerts[].pluginid`, `alertRef` | Keep both. Rule identity uses `alertRef` when present, otherwise plugin ID, with a `zap:` namespace; never use title as rule identity |
| `alert`, `name`, `desc`, `solution`, `reference`, `otherinfo`, `cweid`, `wascid`, `sourceid`, `systemic` | Source title/text/references/classification and source-history ID. Treat HTML/text as untrusted. `sourceid` is not automatically the instance HTTP message ID |
| `riskcode`, `riskdesc`, `confidence` | Immutable source severity/confidence; map risk 0/1/2/3 to informational/low/medium/high, unknown codes to unknown with warning; do not manufacture CVSS or CVEs |
| `instances[].id,uri,nodeName,method,param,attack,evidence,otherinfo` | Native ID, full endpoint identity, method, parameter, payload/evidence and locator. Empty parameter normalizes to null while its raw value remains available |
| `count`, actual `instances` length, launcher cap and phases | Reported versus parsed instance counts plus explicit coverage limits. The template's `count` is its included instance count, not proof of all affected endpoints |

The source confidence values are 0 false positive, 1 low, 2 medium, 3 high, 4 user confirmed. Keep these separate from CoreVAPT analyst disposition and validation status; an imported “confirmed” value does not create a local human approval or successful validation. A nonempty alert with no usable instances must create a diagnostic/count discrepancy rather than disappear. [ZAP alert semantics](https://www.zaproxy.org/docs/desktop/start/features/alerts/), [numeric confidence API](https://www.zaproxy.org/docs/api/).

### Greenbone native scan XML

Select **exactly one** data-bearing report `D`, using only these accepted, unnamespaced structures:

1. `/report[results and gmp/version]` for a directly retained data report.
2. `/report/report[results and gmp/version]` for a downloaded native export envelope.
3. `/get_reports_response[@status='200']/report/report[results and gmp/version]` for a full GMP response.

The selector must find one report, match a caller-specified report ID if supplied, and preserve both envelope ID and data-report ID. Reject multiple candidate reports, report collections, nested/delta results, unexpected namespaces, and ambiguous structures. Take records only from **`D/results/result`**. Do not use `//result`; count summaries, previous/delta results and unrelated reports are different data. An envelope with `extension`/`content_type` must identify XML; format identity must agree with the native format. A direct data report needs a manifest documenting its extraction from native XML.

| Path relative to `D` or its direct result | Normalized destination / rule |
| --- | --- |
| `@id`, `gmp/version`, `task/@id`, `task/name`, `scan_start`, `scan_end`, `timestamp`, `scan_run_status` | Report/task/source times and native scan state. `imported_at` is new CoreVAPT time; never overwrite source time |
| `results/@start,@max`, `filters/term`, `result_count/{full,filtered}`, `results/result_count/page` when present | Preserve filters, pagination and each declared denominator separately; compare the selected result count and unique-ID count; lack of metadata means completeness unknown |
| `result/@id`, `nvt/@oid`, `name`, `nvt/name`, `description` | Native result key, `greenbone:{OID}` rule identity, title and evidence text; retain both names when they differ |
| `result/host` **text node**, `host/hostname`, `host/asset/@asset_id`, `result/port` | Asset/hostname/source asset ID; do not concatenate nested hostname text into the address. Parse only exact numeric `port/protocol` forms; `general/tcp` gives `port=null`, `protocol=tcp`, original location retained; `package`/unknown forms remain nonnumeric |
| `severity`, `original_severity`, `threat`, `original_threat`, override fields | Preserve displayed and original values separately. No missing-severity-to-zero conversion. Special negative severities remain source states/diagnostics and are excluded from ordinary vulnerability ranking until their pinned semantics are handled |
| `qod/value`, `qod/type` | Retain 0–100 value and independently nullable type. Empty type with QoD 80 is valid evidence of an unknown type; do not infer a detection method |
| `nvt/severities/severity/{score,value,origin,date}`, severity `@type`, `nvt/cvss_base` | Versioned score/vector/source/date where available; preserve multiple scores. A score alone does not justify guessing CVSS version |
| `nvt/refs/ref/@type,@id`, `nvt/solution/@type` and text, `nvt/tags`, `scan_nvt_version` | Typed references and remediation. Tags require a bounded parser; preserve raw text. Do not equate NVT OID with CVE or fabricate missing references |

Duplicate native UUIDs with different record contents are a **fatal identity conflict** (`malformed` with a detailed reason), not an invitation to silently deduplicate or overwrite records. Exact duplicate records can be counted separately in diagnostics and mapped once under a documented rule. The original artifact always remains intact. Unresolved/invalid asset identities remain historical/unmapped evidence; they cannot authorize dispatch or correlate automatically into a live asset.

For v1's categorical display, explicitly map a valid nonnegative Greenbone source severity: 0 → informational, 0.1–3.9 → low, 4.0–6.9 → medium, 7.0–8.9 → high, 9.0–10.0 → critical. Missing, malformed, out-of-range and special negative values → unknown with the raw source state retained; never clamp them to zero. This is a versioned display mapping and does not create a CVSS vector/version or a new numeric risk score. Preserve NVT base scores and result-level overridden severity independently.

The official protocol documents 22.6/22.7 compatibility, native XML versus Base64 for other formats, pagination, and `lean` omissions; 22.6 adds audit usage, so a generic XML importer must distinguish scan and audit reports. These justify a narrow allowlist, not universal Greenbone support. [GMP 22.7](https://docs.greenbone.net/API/GMP/gmp-22.7.html#command_get_reports), [compatibility changes](https://docs.greenbone.net/API/GMP/gmp-22.7.html#compatibility_changes), [report/export manual](https://docs.greenbone.net/GSM-Manual/gos-24.10/en/reports.html).

## 3. Expected outputs and completion semantics

These are specifications for future authorized implementation, **not commands executed in this research**. The launcher must use a private attempt directory, exact action/scope/profile binding, hard deadline/output limits, shell-free argv, and network enforcement. Persist bytes, logs and receipt before normalization.

| Profile | Required output and receipt | Successful completion / failures |
| --- | --- | --- |
| Nmap discovery | `nmap.xml`, bounded stdout/stderr, package/image identity, exact numeric target/ports, process exit/termination reason, action/attempt/scope hash, start/end, artifact SHA-256 | `termination_reason=completed`, OS exit 0, fully parseable allowed-version XML, final `finished exit="success"`, reconciled requested target/port coverage and no host-timeout indication. Missing/negative evidence gives partial/failed as appropriate; a closed port is a valid completed observation |
| ZAP baseline AF | `baseline.json` plus generated AF plan, output-summary JSON, ZAP log/stdout/stderr, exact installed add-on/template identities, cap, requested origin, crawl/passive phases, queue/wait outcome and receipt | OS exits 0/1/2 can represent a technically completed profile; store alert policy outcome separately. Exit 1 = FAIL alert(s); 2 = WARN with no FAIL; 3 = technical/other failure. JSON and logs/phase evidence must agree; missing report or unreadable summary never succeeds |
| Greenbone import | Original uploaded bytes + manifest, selected report ID/version, parsed/duplicate/rejected counts, filter/pagination/source status, raw locators and import ID | Import pipeline can succeed while assessment/export completeness remains unknown or partial. GMP wrapper status 200 is necessary for that wrapper, not proof of a completed scan; `Done`, reconciled export counts and metadata are separately required to claim complete exported coverage |

Timeout/cancel/output-limit takes precedence over an alert-driven exit; retain valid partial evidence without calling the run complete. XML/JSON truncation is parser rejection with raw bytes/diagnostics retained; do not “repair” it and claim a native success. A crashed attempt without a trustworthy receipt remains `execution_unknown` pending reconciliation, with no automatic rescan. Greenbone import has **no local scanner exit code, live execution receipt or grant consumption**.

Nmap's fixed profile remains TCP connect, `-sV --version-light -n -Pn`, a single allowed numeric IP, an exact TCP-port list and host timeout; no NSE, `-A` or user flags. Service probing sends traffic. `-Pn` makes requested-target accounting necessary rather than allowing host-discovery status alone to establish reachability. [Nmap output](https://nmap.org/book/man-output.html), [version detection](https://nmap.org/book/man-version-detection.html).

For ZAP choose one fixed AF-compatible baseline invocation specification: `zap-baseline.py --auto -t <authorized-origin/> -m 1 -T 1 -P 8090 -J baseline.json -z -silent`, plus the G0-proposed 180-second outer worker deadline that bounds startup and shutdown. The one-minute passive-wait limit and total deadline are conservative design defaults, not a measured completion guarantee; adjust only through a versioned profile after lab timing evidence. The `-z` value is one fixed argv element, never user-supplied options. The launcher-owned `-P 8090` is required because the inspected script otherwise chooses a free random port; it aligns the exact loopback request/return rules in the [safety design](SAFETY_RECOVERY_PILOT_DECISIONS.md). Verify the pinned wrapper/daemon bind and AF path on the actual runtime before availability. Install the required add-ons in the pinned runtime beforehand. The inspected script skips automatic `-addonupdate/-addoninstall` when `-silent` is present; runtime verification must confirm this behavior in the chosen image. Do not permit `--autooff`, `-n`, `-U`, `--hook`, `-u`, `-j`, custom flags or caller-supplied plans in this profile. Some otherwise valid options trigger a legacy fallback even when `--auto` was specified. The generated plan must match the approved baseline-only phase allowlist. [Pinned baseline script](https://github.com/zaproxy/zaproxy/blob/528bdf4c8c808342cb1f12314a2492c8d3e0b551/docker/zap-baseline.py).

Both inspected baseline paths can reset a URL path to its origin root. Therefore v1 accepts **origin-wide authorization only**; path-limited scopes/exclusions keep this profile unavailable until a separate correctly enforced profile exists. The fixed AF plan defaults to **10 passive alerts per rule**. Keep that cap, disclose it, and report coverage as bounded. The JSON `count` cannot prove no suppressed instances. Crawl completion and passive processing within the limit do not mean full site coverage. Never expose its unauthenticated API port to the host/untrusted networks; no public network or update access is needed during the lab run. [Pinned AF helpers](https://github.com/zaproxy/zaproxy/blob/528bdf4c8c808342cb1f12314a2492c8d3e0b551/docker/zap_common.py#L641), [Docker guide](https://www.zaproxy.org/docs/docker/about/), [baseline exit semantics](https://www.zaproxy.org/docs/docker/baseline-scan/).

## 5. Acquire genuine fixtures before adapter acceptance

**Acquisition owner:** scanner/QA lane; coordinator obtains organizer answers. Complete this task at the **WS-01 fixture-selection exit, before WS-04 positive native integration acceptance or G0 is represented as resolving third-tool readiness**. This is a dependency gate, not an elapsed-time promise. Contract shape work may proceed with references clearly labeled; no synthetic/public-reference file silently closes the gate.

Preferred route: obtain an **existing native XML export from an organizer-provided or explicitly authorized lab**. Have its owner provide export-only access or the file; CoreVAPT does not need Greenbone orchestration. If none exists, a new capture requires separate authorized implementation/lab work. Do not generate one by scanning any address in public samples.

Request these properties for a Greenbone acquisition: supported GMP22.6/22.7, native XML rather than anonymous XML/CSV/PDF; one scan report, `details=1`, `lean=0`, `ignore_pagination=1`, no delta report; explicit `usage_type=scan` and report ID; full recorded filter term including minimum QoD and severity levels; source manager/scanner/feed versions/timestamps; original/displayed severity and override setting; `Done` status and source counts. The exporter must verify the native XML format identifier against its own manager rather than assume a copied ID proves availability. The documented default view filters QoD below70, so explicitly request low-QoD inclusion for the fixture set and retain the applied filter. [Native reports and QoD](https://docs.greenbone.net/GSM-Manual/gos-24.10/en/reports.html), [GMP export options](https://docs.greenbone.net/API/GMP/gmp-22.7.html#command_get_reports).

Proposed export request for that future authorized owner, after confirming the manager's version/format availability (not executed here):

```xml
<get_reports report_id="REPORT_UUID"
  format_id="a994b278-1f62-11e1-96ac-406186ea4fc5"
  details="1" lean="0" ignore_pagination="1" usage_type="scan"
  notes_details="1" overrides_details="1"
  filter="apply_overrides=1 levels=chmlgf min_qod=0 rows=-1 first=1"/>
```

This includes low-QoD/log/false-positive source records for transparent handling. It does not ask CoreVAPT to treat them all as actionable vulnerabilities. Preserve the returned wrapper and native data; do not replace them with a hand-written report. Record rejected/omitted fields and any exporter-version differences rather than silently changing the request.

The acquisition manifest must contain source URL/owner or lab ID, written authorization/ROE reference, file collection time, original SHA-256/size, scanner/manager/GMP identity, feed identity/time or explicit unknown, exact export command/options or UI selections, filters/pagination/override settings, declared source result counts, confidentiality/distribution permission, and reviewer. Keep scanner time, export time, acquisition time and import time separate. Unknown facts remain null with limitations.

Original bytes stay private and immutable. If sharing requires redaction, derive a separate file with its own SHA-256, transformation description, source hash and reviewer. Do not claim the redacted hash identifies the untouched scanner output. Keep synthetic edge cases separate; do not edit a native fixture to invent missing coverage. An imported historical fixture needs `execution_id=null`, imported mode and original source time; no fake current run/approval receipt.

## 6. Greenbone-to-Nikto fallback decision

**Keep Greenbone as first choice. Switch the planned third integration to Nikto native JSON import only if the WS-01 acquisition review cannot identify a lawful supported Greenbone export and a concrete authorized source to obtain it.** Resolve this before accepting WS-04 work or committing the third adapter to the integration slice. No promise such as “wait two hours” substitutes for the dependency decision. If Greenbone export is merely incomplete, request the missing manifest fields; if they remain unavailable at the task boundary, do not count that sample.

Nikto is a conditional replacement, not an automatically working integration. Its own positive native fixture/provenance gate must pass first. If neither source is obtainable, keep the third integration unverified and disclose the mandatory requirement gap. Do not relabel Nmap observations as a separate integration or substitute synthetic scanner output.

## 8. Handoff: resolved and still open

**Resolved design:** fixed native selectors/versions; one ZAP AF reporting route and origin-wide limitation; source-field maps and stable artifact-scoped record keys; separate process/policy/import outcomes; explicit native acquisition boundary; conditional Nikto import fallback; metadata-only handling of public fixtures.

**Observed reference facts:** public file bytes, hashes and record structure/counts; Nmap1.05 constant; ZAP template/source behavior and authored test origin; one Greenbone22.6-format sample; inconsistent legacy Greenbone test data; stated licenses. Access date and complete source identities are retained in the manifest.

**Unrun implementation/runtime gates:** executable schemas/parsers, native captures, pinned binaries/images/add-ons/feeds, field-map tests, worker receipts, safe launcher/egress behavior, actual import/API persistence, UI/report traceability and R05/A12–A14/A35 acceptance.

**Organizer-dependent:** authorized target/credentials/ROE; baseline crawling/service-probe limits; permission to obtain/share lab exports; whether an external historical native import is acceptable evidence for the final demonstration; allowed active validation and its distinct approval/outcome. Section6 explicitly allows supported imports, but it does not prove a specific public fixture will be accepted as a working integration. No organizer was contacted in this research.
